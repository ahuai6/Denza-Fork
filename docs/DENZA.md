# Denza-Fork：在线音乐、同步歌单与译文草稿

基于 Cadenza 3.2.9，版本 `3.2.9-denza.2`。本分支只增加以下能力，保留原播放器、节奏分析、渲染、Hi-Fi 和歌词保存规则。

## 使用

- 音乐库 → 在线音乐：在网易云、QQ 音乐、酷狗、Apple Music 搜索歌曲，选择下载位置、期望音质和歌词字段，单首或勾选下载。AM 还可粘贴歌曲、专辑或公开歌单链接，读取后使用同一下载入口。
- 在线音乐 → 下载：查看进度、已收字节、来源、请求/实际音质和歌词写入结果，暂停、取消和重试。搜索下载加入队列后自动进入列表。暂停后重试会从头下载，不是断点续传。已落盘但入库中断的任务会优先重新入库。
- 在线音乐 → 账号：使用平台 App 扫描二维码，再点击“确认登录”。也可在展开的凭据区域导入自己的 Cookie 和用户 ID。每个平台保存一个当前账号；更换账号前可退出。
- Apple Music 也在同一平台列表中：在账号页选择后打开 Apple 官方登录窗口，完成后回到应用点击“确认登录”，再在“同步歌单”手动同步。AM 不使用其他平台的扫码或 Cookie 导入入口。
- 音乐库 → 歌单 → 同步歌单：点击平台卡片，再手动取得已登录账号的歌单；歌单使用平台原封面，点入可查看歌曲。歌单保留来源、远端顺序和未下载曲目；已明确匹配的本地歌曲可直接播放，其他歌曲可下载后播放。单次批量下载最多 100 首，可分批操作。
- 播放页/特效歌词编辑、空间歌词编辑、桌面歌词工坊 → 翻译与匹配：选择在线翻译、粘贴译文，或搜索平台歌词作为匹配参考；逐行修改后“应用到草稿”，再用原编辑器的保存/应用按钮完成操作。

同步歌单使用原有 `library.playlists` 数据及本地歌曲 ID，不引入第二份播放器或媒体库。在经典界面与本地歌单分标签显示；空间界面也可通过在线音乐面板访问同一个同步歌单。远端歌单的名称和顺序由再次同步更新，本地编辑不会写回平台。退出账号保留已同步的本地副本。远端缺失的旧歌单保留，不自动删除。

Apple Music 的已匹配本地曲目沿用 Cadenza 播放；远端曲目和歌单使用“在浏览器播放”打开 Apple 官方网页，打开成功后暂停 Cadenza 播放。浏览器可能需要单独登录；其播放、音量、授权、歌词与离线能力由 Apple 提供，不接入 Cadenza 的本地播放时钟、特效或 Hi-Fi。未匹配且无目录 ID 的上传歌曲仍保留在歌单，入口打开官方资料库。AM 文件下载通过单独的 LyricsFlow 公开 HTTP 音频服务进入原下载队列，完成后按本地歌曲播放；官方 App 的离线保存仍由 Apple 管理。无目录 ID 的上传曲目无法通过目录下载接口获取。

AM 账号接口参考用户提供的 LyricsFlow Downloader 1.3.0 源码重写。音频文件服务的客户端只构造公开 HTTP 请求并验证响应，不实现音频解密、密钥提取或服务端算法。本版使用 Apple 网页公开的开发者令牌和登录窗口产生的用户令牌取得搜索、地区与歌单；依赖网页版本和接口现状，Apple 改版可能导致读取失败。只在验证账号后保存，不提交不完整的歌单分页。账号命名空间由登录令牌摘要派生；重新授权产生不同令牌时，旧同步副本保留，可自行删除。

## 翻译

支持 OpenAI Responses、OpenAI 兼容 Chat Completions/Responses、DeepSeek 和官方 Codex App Server 登录。模型可手动填写或取得列表；兼容服务地址、协议和模型由用户选择。原词以整曲逐行纯文本与歌曲资料发送，逐字时间戳不会发给模型；译文只按整行生成。可填写术语/上下文要求并锁定已有译文。

粘贴稿支持纯译文、带时间戳及双语文本。优先采用时间/唯一原文锚点，按顺序的结果明确标为待核对建议；可手动把多个片段关联到一行。平台搜索得到的译文进入匹配稿，不直接替换原词。没有译文的版本只允许预览，不能冒充翻译导入。

本版沿用 Cadenza 的 TTML → LRC 编辑与现有保存目标，不另做 SyncC 的容器/原字段保真写回，也不提前修复上游尚待更新的 TTML 保存接口。本版没有嵌入 SyncC 的本地 GGUF 模型运行时。

## 存储与接口

- `electron/online.cjs` 注册受限 `online:request` IPC，preload 暴露 `cadenzaOnline`，类型在 `src/app/online/types.ts`。
- `platforms.cjs` 重写平台适配，SDK 请求放在可终止的 Worker。平台 SDK 只作为底层协议库；没有复制 Sonora 的应用、存储或播放器。
- `downloads.cjs` 使用任务队列、隐藏暂存文件、格式/时长验证、真实音频规格、无覆盖文件提交及入库恢复。新文件的基础标签及能取得的歌词写入暂存副本后校验；失败时保留完整音频。
- 下载目录由用户选择，完成后加入 Cadenza 的受控目录扫描和既有节奏队列。实际格式和音质以文件读取结果为准，选择某一档位不保证平台提供该规格。
- `library.cjs` 为同步歌单保存 `remote` 元数据，平台歌曲身份与本地文件 ID 分开；完全取得账号歌单及歌曲分页后再提交快照。部分失败、分页重复或账号变化不会覆盖旧副本。
- `translation-service.cjs` 管理 API/官方 Codex 文本任务；原词/译文变换在 `src/lyrics/translation.ts`，经 engine 的公开入口提供给所有界面。
- 账号与 API 密钥只由主进程处理，使用 Electron 系统加密，保存在用户配置目录的 `online.json` 中。渲染器只取得账号摘要和 hasKey，不取得已保存的凭据。不修改 Sonora/SyncC 的配置。
- Apple 官方窗口另使用独立的 `persist:denza-apple-music` Chromium 会话保存网站 Cookie；没有应用 preload 或 Node 权限，仅允许指定 Apple 站点的窗口导航。确认时验证并加密保存用户令牌；退出账号清除此专用会话，不清理其他平台或系统浏览器的数据。
- 网络翻译、粘贴匹配、搜索和预览不写音乐文件。最终保存仍由 Cadenza 原接口执行，包含其当前的 Hi-Fi 文件占用协调。

## 测试与边界

`npm run typecheck`、`npm test`、`npm run format:check`、`npm run build:app` 为基本检查。新增 `tests/unit/online.test.ts` 覆盖匹配、原时间信息、凭据、分页、下载提交与现有库歌单关联；`node tests/online-desktop.cjs` 检查界面流程（模拟提供者和写盘，不代表真实账号验证）。`node tests/online-electron.cjs` 使用独立配置与合成音乐库验证真实主进程、IPC、官方 Codex 运行时和工坊退出。可用 `CHROMIUM_PATH` 指定界面测试浏览器，`DENZA_SHOTS` 指定截图目录。

平台搜索、歌词、取链受网络、地区、账号权益和上游接口影响。本客户端不新增音频解密或密钥处理逻辑，不把试听片段当完整下载；第三方服务行为、授权及可用性不能由客户端或用途提示保证。实际会员取链、真人扫码和 OAuth 授权、Windows 文件占用、WASAPI 与实体 GPU/声卡必须分别实测，不能用模拟服务测试代替。

## 手动同步主仓库

`upstream` 为 `ahuai6/Cadenza`，`origin` 为 `ahuai6/Denza-Fork`。仅在用户要求时更新 `upstream-main`，再把上游提交合并到 `custom` 并验证；不重置覆盖定制提交。此功能不添加定时同步，不修改主仓库。原项目的 main/space-mode 发布触发规则保持原样；本功能分支不自动发布安装包。

## 后续开发与 API 更新

下载、账号歌单、在线翻译和歌词匹配直接在 Denza-Fork 维护，不跟随 Sonora、SyncC 或 LyricsFlow 的后续功能提交。Cadenza 主程序及各底层 API/SDK 分开评估和更新，详见 [架构与维护边界](DENZA-ARCHITECTURE.md)；依赖只读检查使用 `npm run online:deps`。

## AM 公开文件服务

AM 搜索、账号和歌单仍使用 Apple 接口；文件请求独立使用 `https://api.trylyricsflow.com`，不发送 Apple Cookie、用户令牌或翻译 API 密钥。依据服务当前 OpenAPI 2.0.0：MP3/FLAC 使用 `/download/{fmt}?song=<目录ID>&mode=apple`，AAC/ALAC 使用 `/download?song=<目录ID>&codec=<格式>&mode=gamdl&fallback=false`，可附地区。`gamdl` 是服务端公开参数，不对应本地解密实现。无需跟随 LyricsFlow Downloader 应用的后续版本即可更新该服务适配。

在 AM 平台下，格式菜单直接显示 MP3、AAC、FLAC、ALAC；“全部平台”的通用四档分别映射到以上格式。ALAC 不代表一定取得高采样率，FLAC/ALAC 容器也不能证明源音频的制作质量。只有实际规格会在任务里显示。服务器准备响应最多等待 3 分钟，传输空闲超过 45 秒取消；支持主动取消、重试与不覆盖文件的入库恢复。文件 magic、实际 codec 和歌曲时长逐次验证。所选格式不可用时逐档回退，列表显示请求和实际档位；最低档仍无法验证则失败。不按扩展名伪装格式，不切换其他音乐平台作为来源。

经典和空间设置的 Denza-Fork 分组显示“内容仅供个人学习使用，请于下载后24小时内自行删除”，并说明此提示不构成下载授权或免责。提示不触发自动删除，不是合法性保证。应仅下载有权取得的内容；第三方服务的版权授权、稳定性及实际音乐返回未在本环境验证。歌词编辑仍沿用当前 Cadenza 保存流程；下载歌词通过该服务的 `/lyrics` 读取，目录匹配失败或空结果时尝试 `/lyrics/by-metadata`。

## 下载质量、歌词与界面修复

手动音质按平台保存；全平台搜索另有自己的选择，不会因某首歌降档而更改偏好。原生取链失败后尝试 Sonora 中参考的独立公开 HTTP 来源（Jerry、Mxin、Sakurink），只发送平台/歌曲 ID/档位，不发送平台登录凭据。同一档位的原生文件失效时也会尝试替代来源，再按 Hi-Res → 无损 → 高 → 标准向下回退。AM 四档仍分别表示 ALAC、FLAC、AAC、MP3，不能将 ALAC 等同于 Hi-Res 采样率。列表同时显示实际 codec、位深、采样率和码率。

“内嵌歌词字段”可选择 LRC + TTML、仅 LRC、仅 TTML 或不内嵌，选择在入队时固定到每个任务。MP3 的 TTML 使用独立 TXXX:TTML，FLAC 使用 TTML 注释，M4A 使用 com.apple.iTunes:TTML，常规 LRC 使用各容器的标准歌词标签。下载先写入临时副本，再回读字段与时长；写入失败保留已验证的原音频并显示提示。原生 TTML 原文保留；只有 LRC 时使用 Cadenza 的纯解析逻辑转换，并明确标注转换结果不具有原生逐字时间。没有歌词时明确显示未取得，不伪造时间信息。原编辑器的保存接口未改动。

酷狗同步优先使用账号云歌单接口及私有 listid，只有已取得对应 global_collection_id 时才允许公开接口回退。歌单同步仍需取得完整快照，失败保留旧副本。在线和同步歌曲复用原封面组件，歌单卡片样式抽出为共享 CSS；平台入口为自行绘制的几何图形。

翻译与匹配改为来源/逐行核对双栏，小屏堆叠；下拉选项在当前弹窗内显示，避免被遮挡。音乐库切换页不再同时挂载退场页和入场页，防止嵌套在线页面及其弹层重叠。
