## AM 公开 HTTP 文件服务追加验证

- 核查了用户提供的 `src/api.js`、`src/jobs.js` 和 `https://api.trylyricsflow.com/openapi.json`。服务规格当前为 2.0.0；新增实现是公开 HTTP 文件客户端，没有新增客户端音频解密、密钥提取或服务端算法。
- AM 可在统一搜索/同步歌单入口下载 MP3、AAC、FLAC、ALAC，官方浏览器播放继续保留。Apple 登录令牌与服务调用分开；请求只构造目录 ID、格式/模式及可选地区，不带 Apple Cookie、用户令牌或翻译密钥。
- 全量测试：37 个文件、391 项通过。最后针对格式/时长与错误响应补充断言后，五个相关文件的 41 项测试、类型和格式检查通过；应用构建通过。
- 新的四项服务测试使用本地 HTTP 服务与自行生成的一秒正弦波文件，完整验证四种格式的流式下载、真实 codec/时长、标签回读、原库导入；ALAC 请求返回 AAC 时失败且不入库。覆盖目录 ID 缺失、凭据不外发、短曲目试听检测、取消、重定向与 HTML 拒绝。测试不依赖外部 FFmpeg 安装，生成命令随测试素材说明保存。
- 使用桌面实际的 Electron 文件网络层读取公开 OpenAPI，HTTP 200，返回标题/版本正确。普通 Node 的直接外网探测在本环境失败，生产服务传输使用 Electron 网络层；没有请求真实商业音频下载，也没有测试服务端行为或版权授权。
- 更新后的界面流程通过：AM 下载入口启用、官方播放保留、经典设置的 Fork 提示存在。经典与空间使用同一提醒组件；没有自动删除或授权确认开关。截图已查看，原有 Linux 软件绘图及完整图形回归限制仍保留。
- 真实 Electron 检查通过：官方播放链接、持久化歌单、未选下载目录时明确拒绝入队、Codex 运行时及工坊退出，无资源 404。未使用真人账号或订阅。
